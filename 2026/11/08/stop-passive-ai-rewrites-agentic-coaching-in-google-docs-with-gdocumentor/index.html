A Go CLI and MCP server that turns Gemini and any AI agent into a Socratic writing and code review coach

Figure 1. Overview of the gdocumentor architecture and its four core pillars.

In my previous two articles—Building a Multimodal, Suggestion-Based AI Writing Coach with Gemini and Google Docs (Ref) and Beyond Passive AI Rewrites and Vibe Coding in Google Docs (Ref)—I introduced the Google Apps Script add-on DocuMentor AI (Ref). Those earlier articles explain the foundational inspiration behind the project, how programmatic Google Docs API (v1) suggestions and comments (Ref) can replace passive AI ghostwriting with active learning, and how a single Google Docs container-bound or Marketplace script can serve both individuals and school/enterprise domains. For background on those foundational concepts and the Google Apps Script implementation, please refer to those two published articles (Ref, Ref).

In this third installment, I introduce gdocumentor (Ref)—a high-performance Golang CLI tool, Global Model Context Protocol (MCP) Server (gdocumentor mcp), and Google Antigravity Agent Skill / Plugin (with support for 7 major AI agent environments) that liberates DocuMentor AI from the confines of a single open browser tab and transforms it into a 1-to-N scriptable, terminal-native, and autonomous AI-agent-driven coaching and document automation platform.

The 4 Core Pillars (Figure 1)

  • 1. Multi-Source Input & Scoped Workspace: Ingests local files (.md, .pdf, .docx, .txt, source code), stdin, Web/GitHub URLs (#Lstart-Lend), and Google Docs (-d <docId>), with scoped line/character ranges (-t, --range) and automatic cross-file dependency discovery (--auto-deps).
  • 2. Parallel Pipeline, RAG Persona & Dual AI Engine: Runs concurrent Go goroutine I/O (sync.WaitGroup) with custom personas (--persona) and RAG rulebooks (-r). Standalone CLI Mode calls the built-in Gemini API (gemini-3.8-flash / gemini-4-argon) via GEMINI_API_KEY, while MCP Server Mode (gdocumentor mcp) uses the client AI agent’s own LLM (Host AI) (no GEMINI_API_KEY required).
  • 3. Dual Coaching Modes, 0-Token Direct Editing & Decision Record: Supports Google Docs OAuth2 Mode (bottom-up UTF-16 WriteMode.SUGGEST inline edits, Socratic --hint comments, and a 🎓 DocuMentor AI Summary tab via --summary-tab), Zero-Auth Local Mode (--no-auth) for local Markdown reports (-o), 0-Token Direct Editing (edit) for Markdown/table/image insertion and resizing, and Decision Record tracking (Accepted, Edited, Rejected, Expired).
  • 4. Universal Interfaces & Multi-Agent MCP: Provides an interactive CLI TUI, a pure JSON stream (--json), and 6 MCP tools (proofread, summary, inspect, draft, edit, manage).

1. Defining the Problem & Why Move Beyond a Browser Add-on

Why Passive AI Rewrites Fail

  • Cognitive Debt (MIT Media Lab, June 2025): Passively accepting AI text measurably reduces brain activity and neural connectivity (Ref).
  • The “Shortcut Trap” (CMU, Wharton & MIT, 2026): Just 10 minutes of passive AI reliance drops independent problem-solving performance by 20% (Ref, Ref).
  • Declining Thinking Skills (Nikkei XTECH, Oct 2026): 42.1% of AI users cite declining thinking ability as their #1 concern (Ref).

Instead of silently overwriting text, gdocumentor enforces active human judgment:

  • Suggest Mode: Proposes inline diffs (WriteMode.SUGGEST) paired with 💡 Reason and 🎓 Learning Point replies.
  • Socratic Hint Mode (--hint): Withholds the rewritten answer and attaches only diagnostic hints so the human author writes the fix.

Two Limits of a Browser Add-on

  • 1. 1-to-1 Browser Constraint: A Google Apps Script sidebar only works on one open browser tab at a time (with a 6-minute execution limit).
  • 2. Locked to Internal Gemini API: A browser add-on cannot delegate reasoning to external AI agents (Antigravity, Claude Desktop, Cursor, VS Code) that you already use.

2. Architecture: 4-Stage Pipeline & Dual-Engine MCP

A. The 4-Stage Processing Pipeline

Figure 3. End-to-end workflow and 4-stage processing pipeline of gdocumentor.

  • Stage 1 — Input, Scope & Context: Loads targets, marks --target / --range blocks editable (retaining surrounding lines as read-only context), resolves --auto-deps and -r RAG rules, and converts Markdown + local images into Pageless Google Docs.
  • Stage 2 — Dual-Engine AI Inference: Standalone CLI packs text rules/context into XML blocks, uploads PDFs/visuals to the Gemini File API, and calls gemini-3.8-flash / gemini-4-argon; MCP Server delegates reasoning to the client AI agent’s own LLM (model: "agent-ai").
  • Stage 3 — Surrogate-Pair-Safe UTF-16 Matching (utf16idx): Maps edits to exact UTF-16 [StartIndex, EndIndex) offsets, filters out read-only scopes, and sorts bottom-to-top (StartIndex descending) to prevent index drift.
  • Stage 4 — Two-Phase Application: Phase 1 applies WriteMode.SUGGEST replacements + addCommentReply rationales (or insertComment in --hint mode); Phase 2 re-fetches coordinates to anchor VISUAL_N / TABLE_N comments, builds the 🎓 DocuMentor AI Summary tab, and updates the Decision Record (or writes a local Markdown report in --no-auth mode).

C. 10 Standout Capabilities of gdocumentor

  • 1. Zero-GEMINI_API_KEY Host-AI MCP + Standalone CLI Dual Engine: Delegates reasoning to your AI agent’s own LLM (gdocumentor mcp) with no extra API key, or runs as a self-contained CLI via GEMINI_API_KEY.
  • 2. Zero-Drift UTF-16 Coordinate Matching (utf16idx): Converts UTF-8 to surrogate-pair-safe UTF-16 offsets and applies batchUpdate edits bottom-to-top (StartIndex descending) so character indices never shift.
  • 3. Socratic --hint Mode & Rationale Replies: Replaces passive ghostwriting with WriteMode.SUGGEST diffs + 💡 Reason / 🎓 Learning Point replies, or withholds answers entirely (--hint) so authors revise text themselves.
  • 4. Multimodal Prose × Table (TABLE_1) × Figure (VISUAL_1) Verification: Cross-checks narrative claims against embedded images and tables, anchoring comments directly onto mismatched figures or tables.
  • 5. Fail-Closed Line/Char Scoping (--target) + Auto-Dependencies (--auto-deps): Restricts edits strictly to specified ranges (#L1-L35, @0:2500) while automatically attaching imported files as read-only context.
  • 6. 4-State Decision Record & Learning from Both AI (🤖 AI) and Human (👤 Human) Reviews (summary): Tracks Accepted, Edited (via bigram similarity), Rejected, and Expired outcomes, while gdocumentor summary analyzes existing suggestions and comments—including those written by human colleagues, instructors, or peer reviewers (👤 Human) as well as AI (🤖 AI)—to synthesize personalized writing/coding habits and actionable learning advice.
  • 7. Zero-Auth Local Mode (--no-auth): Runs 100% locally without Google Cloud or OAuth2 tokens to output Markdown diff reports (-o).
  • 8. 0-Token Direct Google Docs Editor (gdocumentor edit): Creates Pageless Docs, converts/inserts rich Markdown + tables + local images, and resizes VISUAL_1 in place without consuming a single LLM token.
  • 9. 7-Client Installer (gdocumentor setup) & Windows 11 ↔ WSL2 Bridge (--wsl-host): Auto-configures Antigravity, Claude Desktop, Claude Code, Cursor, VS Code, Windsurf, and Gemini CLI—including a 1-command wsl.exe bridge with automatic C:\... ⇄ /mnt/c/... path translation.
  • 10. 1-to-N Parallel Batch Scaling & Multi-Language Coaching (-l): Processes multiple Google Docs concurrently and outputs coaching feedback in any target language (-l en, ja, de, fr, es, zh, ko, auto).

D. Why Build gdocumentor in Go (Golang)?

  • Zero-Dependency Single Static Binary (CGO_ENABLED=0): No Python venv or Node.js node_modules—a single binary runs out of the box on macOS, Linux, and Windows (amd64 / arm64).
  • Millisecond Cold Starts for MCP stdio & WSL2 Bridges: Instant subprocess startup keeps multi-step MCP tool chains (inspect ➔ edit ➔ proofread) snappy even across wsl.exe.
  • Goroutine Concurrency (sync.WaitGroup) with No Time Limits: Loads files, converts Base64 images, uploads Gemini File API assets, and processes 1-to-N Google Docs in parallel without GAS’s 6-minute ceiling.
  • Native rune & unicode/utf16 Precision: Fast, type-safe conversion between UTF-8 strings and Google Docs API UTF-16 code units.
  • Guaranteed defer Cleanup & Shared Type Safety: Automatically cleans up temporary cloud/local files on exit (defer) and shares 100% identical structs across Standalone CLI and MCP Server modes.

E. Why Self-Provisioning (gdocumentor setup) & WSL2 ↔ Windows Cross-OS Bridging Are Unique

  • Push-Based Self-Provisioning Binary (Zero npx / uv Dependencies): Unlike client-side pull commands (claude mcp add, code --add-mcp) or external Node/Python installers (Smithery, FastMCP), the compiled gdocumentor binary itself knows every client’s OS config path and JSON schema (mcpServers vs. VS Code’s servers) and non-destructively merges its own setup in one command.
  • Simultaneous MCP Server + Native Agent Skill/Rule Deployment: Existing MCP installers only register JSON server entries, leaving the Host AI unaware of workflow rules; gdocumentor setup simultaneously installs native coaching skills, rules, and subagents across all 7 clients (SKILL.md, .cursor/rules/gdocumentor-workflow.mdc, .github/instructions/gdocumentor.instructions.md, .windsurf/rules/gdocumentor-workflow.md, rules/gdocumentor-workflow.md, agents/gdocumentor-coach.md).
  • 1-Command WSL2 ➔ Windows Host Cross-OS Bridge (--wsl-host): Previously, connecting Windows GUI clients (Claude Desktop, Cursor, VS Code, Windsurf) to a WSL2 MCP server required manually editing %APPDATA% JSON files or fragile bash -c scripts; running gdocumentor setup --all --wsl-host inside WSL2 auto-detects the Windows user profile under /mnt/c/Users/<WinUser>, updates Windows-side config files directly, and injects a shell-free wsl.exe --exec bridge.
  • Unified OAuth2 Credentials & Lifecycle Management (--status / --uninstall): All Windows GUI clients and WSL2 CLI agents share a single Linux-side gdocumentor binary, Google Application Default Credentials (~/.config/gcloud/application_default_credentials.json), and Decision Records (~/.config/gdocumentor/decision_records/), with built-in cross-OS status diagnostics (--status) and clean non-destructive removal (--uninstall).

Command 5: Structural Inspection, Decision Record & Learning from AI + Human Reviews (inspect, manage, & summary)

  • 🔑 Credentials: inspect / manage: 0 Gemini tokens (GEMINI_API_KEY Not Required) | summary: GEMINI_API_KEY Required in CLI mode (or 0 GEMINI_API_KEY via Host-AI MCP) | Google OAuth2: Required
  • 🎯 What it does: Inspects exact UTF-16 coordinates (inspect), tracks how authors respond to suggestions (manage), and analyzes both AI-generated (🤖 AI) and human-authored (👤 Human) suggestions and comments on a Google Doc (summary) to give the author actionable learning advice.
# 1. Inspect paragraph coordinates (@start:end), visual/table IDs, and pending AI/Human suggestions (0 LLM tokens)
./gdocumentor inspect -d "<YOUR_GOOGLE_DOC_ID>"

# 2. Analyze existing suggestions & comments (from BOTH AI and human reviewers, including resolved history) to get learning advice
./gdocumentor summary -d "<YOUR_GOOGLE_DOC_ID>" --include-resolved --summary-tab

# 3. Accept all pending suggestions and update the Coach Impact & Decision Record (0 LLM tokens)
./gdocumentor manage -d "<YOUR_GOOGLE_DOC_ID>" --accept-all
  • Structural Inspection (inspect): Prints all tabs, paragraph UTF-16 @start:end coordinates, VISUAL_N / TABLE_N IDs, active suggestions (🤖 AI vs. 👤 Human), and Decision Record counters with 0 LLM tokens.
  • Learning Advice from AI & Human Reviews (summary): Reads all open and resolved (--include-resolved) inline suggestions and comment threads on the Google Document—not only those created by generative AI (🤖 AI), but also edits and comments left by human colleagues, teachers, or editors (👤 Human)—and generates a Writing Coach & Learning Summary (explaining why each human or AI edit matters, recurring weak points/habits, and concrete tips for future writing) without modifying the document text.
  • Decision Reconciliation (manage --accept-all): Accepts pending suggestions and reconciles ~/.config/gdocumentor/decision_records/<docId>.json into ✅ Accepted, ✏️ Edited (author refined the text), ❌ Rejected, or 🗑️ Expired (>7 days or deleted), computing the Draft Improvement Rate while separating AI (🤖 AI) from human (👤 Human) edits.
