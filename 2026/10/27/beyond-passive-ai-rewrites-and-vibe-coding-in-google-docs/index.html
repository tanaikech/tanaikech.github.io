Scaling a Multimodal AI Writing and Code Review Coach Across Classrooms and Research Labs with Gemini and Google Apps Script

In my previous article—Building a Multimodal, Suggestion-Based AI Writing Coach with Gemini and Google Docs—I introduced DocuMentor AI, an open-source Google Docs add-on built with Google Apps Script, the Google Docs API (v1), and the Gemini API (gemini-3.8-flash / gemini-4-argon). Instead of overwriting a writer’s draft directly, DocuMentor AI uses the newest Google Docs API Suggestion & Comment Management features (WriteControl.writeMode = "SUGGEST", addCommentReply, insertComment, acceptSuggestion, rejectSuggestion, and deleteComment) to turn Google Docs into an interactive, multimodal writing coach.

Shortly after publishing that first article, I received enthusiastic feedback from educators, Google Developer Experts (GDEs), academic researchers, and enterprise practitioners. While they loved how the tool preserves author agency—especially through 💡 Hint-Only Mode and the 🎓 Writing Coach & Learning Summary dialog—they raised a crucial practical question for schools, universities, and organizations:

“How can we deploy DocuMentor AI across a school, university lab, or company domain where students and end users are not allowed to access Google AI Studio to create their own Gemini API keys—without risking an API key leak in a shared Google Doc, and without asking non-coder IT administrators to rewrite JavaScript code?”

At the same time, while reflecting on how DocuMentor AI’s underlying engine works, I came up with another new idea of my own: because DocuMentor AI extracts every line in a Google Doc as an independent block and applies non-destructive inline diffs (WriteMode.SUGGEST), Socratic hints (insertComment), and educational replies (addCommentReply), what if we use it not only for natural-language manuscripts, but also as an interactive Code Review & Programming Coach for software engineers and computer science students? Rather than blindly copy-pasting AI-generated scripts (“vibe coding”), learners could paste source code written in any programming language (Python, JavaScript, TypeScript, Go, Java, C++, Rust, SQL, Google Apps Script, etc.) into Google Docs and learn what is wrong in their code, why it fails, and how to fix it line by line.

1. The Deployment Challenge in Education, Research Labs & Organizations

When an individual developer or writer uses DocuMentor AI on their personal Google account, pasting a personal Gemini API key into the sidebar (stored in PropertiesService.getUserProperties()) is quick and straightforward.

However, in Google Workspace for Education, university research laboratories, and corporate environments, three structural barriers arise:

  1. Google AI Studio Is Restricted for Students & Non-Technical Users: In most K–12 schools and universities using Google Workspace for Education, access to Google AI Studio is disabled for student Organizational Units (OUs)—especially for under-18 students—and requiring every student, researcher, or staff member to generate and manage their own API key is a major adoption bottleneck.
  2. Sharing a Container-Bound Google Doc Risks API Key Exposure & Wipes ScriptProperties on Copy: If a teacher or administrator simply pastes the script into a shared Google Docs template, any student with Editor access to that document can open Extensions > Apps Script and inspect the project settings. Furthermore, when Google Classroom creates individual student copies of an assignment document (“Make a copy for each student”), Google Apps Script intentionally strips all ScriptProperties from the copied files for security reasons.
  3. Most School & Department IT Administrators Are Non-Coders: If deploying an internal tool requires editing source code to hardcode credentials or rewrite authentication flows, many school and departmental IT staff will be unable to maintain it.

2. How v1.0.3 Solves This with a Single Unified Script

To address all three barriers without splitting the project into separate “Personal” and “Enterprise/Edu” editions, DocuMentor AI v1.0.3 introduces two core architectural upgrades in src/code.js and src/index.html.

A. Priority-Locked Dual API Key Resolution (ScriptProperties ➔ UserProperties)

In v1.0.3, the backend helper getEffectiveApiKeyInfo_() checks two storage scopes in strict priority order:

function getEffectiveApiKeyInfo_() {
  try {
    const scriptProps = PropertiesService.getScriptProperties();
    const scriptKey = scriptProps
      ? scriptProps.getProperty("GEMINI_API_KEY")
      : null;
    if (scriptKey && scriptKey.trim().length > 0) {
      return {
        apiKey: scriptKey.trim(),
        hasApiKey: true,
        apiKeySource: "script",
      };
    }
  } catch (e) {}

  try {
    const userProps = PropertiesService.getUserProperties();
    const userKey = userProps ? userProps.getProperty("GEMINI_API_KEY") : null;
    if (userKey && userKey.trim().length > 0) {
      return {
        apiKey: userKey.trim(),
        hasApiKey: true,
        apiKeySource: "user",
      };
    }
  } catch (e) {}

  return {
    apiKey: "",
    hasApiKey: false,
    apiKeySource: "none",
  };
}

Here is how this single function behaves across both environments without a single line of code modification:

  • 🏫 Admin-Managed Mode (apiKeySource === 'script'): The IT administrator opens the Apps Script visual interface (Project Settings ⚙️ > Script Properties), clicks Add script property, and registers GEMINI_API_KEY once. Because ScriptProperties takes top priority, DocuMentor AI automatically locks into Admin-Managed Mode.
  • 🔒 Locked Student / Organization Sidebar UI: When any student, faculty member, or employee opens the sidebar under Admin-Managed Mode, the API key input field and the Reset button are completely hidden and replaced with a locked status badge (🔒 API Key Configured (School / Organization Admin)). Furthermore, both saveApiKey() and deleteApiKey() ignore client-side overrides when apiKeySource === 'script'—meaning students cannot clear, overwrite, or inspect the organization’s API key even from browser developer tools.
  • 👤 Individual User Mode (apiKeySource === 'user' or 'none'): Individual users do not touch Project Settings ⚙️ > Script Properties, so ScriptProperties remains empty. The sidebar behaves 100% identically to previous versions: displaying the API key input box on first launch, saving the user’s personal key into UserProperties, and showing 🔒 API Key Configured (Saved) with a Reset button (as shown at the top of the v1.0.3 sidebar in Section 4 below).

B. Dual Menu Registration for Both Private Marketplace Add-ons and Container-Bound Scripts (onOpen & onInstall)

When a script is published as a Google Workspace Marketplace Editor Add-on, Google Docs executes onOpen(e) in ScriptApp.AuthMode.NONE until the user interacts with the add-on, and requires menus to be registered via DocumentApp.getUi().createAddonMenu() (which places the menu under Extensions > DocuMentor AI). Conversely, personal container-bound scripts typically use createMenu('✦ DocuMentor AI') to display a top-level menu in the Google Docs toolbar.

In v1.0.3, onOpen(e) and onInstall(e) seamlessly support both execution environments in one place:

function onInstall(e) {
  onOpen(e);
}

function onOpen(e) {
  const ui = DocumentApp.getUi();
  try {
    ui.createAddonMenu().addItem("Open Dashboard", "showSidebar").addToUi();
  } catch (err) {}

  if (!e || e.authMode !== ScriptApp.AuthMode.NONE) {
    try {
      ui.createMenu("✦ DocuMentor AI")
        .addItem("Open Dashboard", "showSidebar")
        .addToUi();
    } catch (err) {}
  }
}

3. Why DocuMentor AI Is Transformative for Academia, Scientific Research, Higher Education & Engineering Training

While DocuMentor AI is a versatile writing coach for everyday business documents and K–12 classrooms, its architecture—combining Google Docs API v1 Suggestion/Comment management with Gemini’s multimodal reasoning—makes it uniquely powerful for academic researchers, university laboratories, graduate students, scientific authors, and software engineering learners.

As illustrated in the workflow infographic above, DocuMentor AI operates through a three-stage multimodal pipeline designed specifically for active learning, scholarly rigor, and engineering code review:

  1. Stage 1 — Manuscript, Code & Review History Extraction: When a researcher, student, or developer runs the tool on a Google Doc (or a highlighted section via 🎯 Proofread Selection Only), the backend inspects the active document tab via documents.get with suggestionsViewMode=PREVIEW_SUGGESTIONS_ACCEPTED and commentsViewMode=COMMENTS_VIEW_MODE_INCLUDED. It simultaneously extracts body text and research claims, source code and scripts in any programming language (Python, JavaScript, TypeScript, Go, Java, C++, SQL, Google Apps Script, etc., line by line), structured data tables (TABLE_1, TABLE_2, …), embedded charts and figures as binary images (VISUAL_1, VISUAL_2, …), and both active and resolved review threads (including previously accepted or rejected inline edits and resolved comments from advisors, co-authors, or code reviewers).
  2. Stage 2 — Gemini File API & Docs API v1 Engine: The extracted Markdown context and binary figure images are uploaded in parallel to the Gemini File API (fileData.fileUri) and analyzed by gemini-4-argon or gemini-3.8-flash. During this phase, the engine performs cross-modal and spec-to-code verification (checking whether claims, baselines, or implementation scripts match the numbers, units, and architecture diagrams in tables and figures), conducts rejection-aware history analysis (adapting its edit granularity based on what the author previously accepted or rejected), and prepares reverse-index line and phrase batch requests (startIndex descending) so multiple edits never shift downstream character offsets.
  3. Stage 3 — Interactive Coaching in Google Docs: Rather than silently overwriting the manuscript or script, the engine delivers three complementary outputs directly inside Google Docs: 💡 Hint-Only Mode (insertComment writing and debugging hints without spoiling the rewrite), 🚀 Suggest & Coach Mode (WriteMode.SUGGEST surgical prose and code diffs paired with addCommentReply explanations), and the 🎓 Learning Summary Dialog synthesizing overall evaluation, recurring writing and coding habits, and actionable next steps.

This architecture directly addresses five critical challenges across academic research, classroom education, and software engineer training:

1. Combating “Cognitive Debt” and “Cognitive Surrender” in Academic & Student Writing

Recent cognitive science research has sounded the alarm on passive AI reliance:

  • MIT Media Lab Brain Study (June 2025): The study “Your Brain on ChatGPT” demonstrated that passively accepting AI-generated text induces “cognitive debt,” measurably reducing neural connectivity and mental engagement (Ref).
  • CMU, Wharton & MIT Studies (2026): Subsequent research highlighted the “shortcut trap”—where even 10 minutes of AI reliance reduces subsequent independent problem-solving performance by 20% (Ref)—and “cognitive surrender,” where fluent AI outputs create an illusion of competence that stops students from thinking critically (Ref).
  • Nikkei XTECH Survey (October 2026): In this survey, 42.1% of generative AI users cited “decline in thinking ability due to AI dependency” as their #1 concern (Ref).

In universities and schools, faculty often hesitate to permit AI tools because conventional rewriters turn students into passive copy-pasters. DocuMentor AI flips this dynamic by requiring authors to either formulate their own revisions from anchored coaching hints (💡 Hint-Only Mode) or critically evaluate each transparent diff paired with its grammatical/logical reason (🚀 Suggest & Coach Mode).

2. True Cross-Modal Consistency Verification (Prose ⇄ Tables ⇄ Figures) for Research Papers

Academic manuscripts—such as journal articles, conference papers, theses, and grant proposals—never consist of prose alone. One of the most common reasons peer reviewers flag scientific drafts is cross-modal inconsistency:

  • Mismatched Baselines & Metrics: Numbers or percentages cited in the Results text do not match the values or baselines in Table 1 or Figure 1.
  • Inconsistent Units & Labels: Axis labels, units, or terminology in a bar chart or architecture diagram (Execution Time (Minutes)) differ from the column headers in a table (Task Time).
  • Uncited Visuals: Figures and tables are inserted into the manuscript without being explicitly cited or interpreted in the narrative.

Because DocuMentor AI uploads the manuscript’s structured Markdown and binary figure images in parallel to the Gemini File API, gemini-4-argon inspects the actual visual pixels of your plots alongside your tables and prose—proposing inline cell edits (WriteMode.SUGGEST) and attaching anchored review comments (insertComment) directly onto every figure and table.

3. Distilling Co-Author, Advisor & Peer-Review History into Long-Term Learning (INCLUDE_RESOLVED_HISTORY)

In academic labs and graduate programs, a Google Doc often accumulates dozens of inline suggestions and comment threads from a principal investigator (PI), thesis advisor, or co-authors. Once a student clicks Accept on the advisor’s edits or Resolve on comment threads, that valuable pedagogical feedback normally disappears into the document’s history.

With DocuMentor AI, calling documents.get with commentsViewMode=COMMENTS_VIEW_MODE_INCLUDED extracts both open review threads and resolved review history (RESOLVED, ACCEPTED, REJECTED):

  • Step 1 History Ledger: Renders an expandable 📜 View Resolved Review History ledger right in the sidebar showing every accepted/rejected edit and resolved comment thread.
  • Rejection-Aware Adaptive Proofreading: When 📜 Include Resolved Review History is enabled during proofreading, Gemini respects the author’s prior rejections (for instance, switching from full-sentence rewrites to surgical phrase-level edits if the author previously rejected broad rewrites).
  • Retrospective Learning Summary: By turning ON 📜 Include Resolved Review History and clicking 🎓 Generate Learning Summary from Suggestions & Comments, graduate students and researchers can synthesize their advisor’s or co-authors’ entire review pass—even after all threads are resolved—into a structured Writing Coach & Learning Summary.

4. Protecting Unpublished Research Data & Scaling Across Classrooms

For universities and schools deploying DocuMentor AI via ScriptProperties, linking the institution’s Google Cloud Billing account (Paid Tier 1+) to the Gemini API project provides two essential guarantees:

  1. Strict Academic & Student Data Privacy: Under Google’s Gemini API Terms of Service for paid/billed projects, submitted manuscripts, tables, and unpublished research figures are never used to train or improve Google models—preserving academic originality and student privacy. Additionally, DocuMentor AI automatically deletes all temporary files from the Gemini File API inside a finally block (deleteGeminiFiles_) immediately after each request.
  2. High Concurrent Throughput & Distributed GAS Quotas: Paid Tier rate limits allow an entire classroom of 30–40 students or a full research department to run multimodal proofreading simultaneously without hitting Free Tier RPM bottlenecks, while Google Apps Script UrlFetchApp quotas are counted per active student/researcher account (20,000–100,000 calls/day per user) rather than sharing a single user’s quota.

5. Beyond Prose: Why DocuMentor AI Is Ideal for Multi-Language Script Learning, Code Review & Engineer Training

While designing and testing DocuMentor AI, I realized that its core mechanism is not limited to natural-language essays or academic papers—it is equally powerful for coaching programming scripts across any language (Python, JavaScript, TypeScript, Go, Java, C++, Rust, SQL, Bash, Google Apps Script, and more).

Just as passive AI text rewriting leads to “cognitive surrender” in essay writing, software engineering education, university computer science courses, and corporate DX (citizen-developer) training face an identical crisis: “vibe coding”—where beginners and junior engineers blindly copy and paste AI-generated code without understanding what was wrong in their original script, why it failed at runtime, or how the underlying language or API actually works.

When we examine both the pedagogical workflow and the internal implementation of src/code.js, three reasons make DocuMentor AI uniquely suited for multi-language script learning and educational code reviews inside Google Docs:

  • 1. Transforming Passive Copy-Pasting into Active, Language-Agnostic Engineering Mentorship: Instead of handing over a rewritten file that replaces the learner’s entire script at once, DocuMentor AI supports two active-learning code review modes for any programming language. In 💡 Hint-Only Mode (insertComment), it acts like a Socratic senior engineer mentor—highlighting the buggy, inefficient, or insecure line of code and explaining the root cause (e.g., an off-by-one error, SQL injection risk, memory leak, unclosed resource, or API misuse) so the learner can debug and refactor the line themselves first. In 🚀 Suggest & Coach Mode (WriteMode.SUGGEST + addCommentReply), it acts like an educational GitHub Pull Request inline diff—crossing out the problematic line, proposing the idiomatic replacement in that target language inline, and attaching a reply with the 💡 Reason for Revision and 🎓 Learning Point, followed by a 🎓 Writing Coach & Learning Summary that diagnoses recurring coding habits across the entire script.
  • 2. High Technical Affinity with DocuMentor AI’s Line-Block & Reverse-Index Engine (src/code.js): Why does Google Docs inline suggestion mode work so cleanly on source code regardless of the programming language? When any script is pasted into Google Docs with normal line breaks (Enter), Step 1 extracts each line of code as an independent paragraph block in editableBlocks ([Block N (Body)]). In Step 2, Gemini’s strict schema rule (each "originalText" MUST be an exact, character-for-character substring found within "Target Editable Settled Text Blocks" without newlines) naturally guides the model to target self-contained, single-line bugs and anti-patterns. Then, in Step 3 (step3_buildRequestBody()), all matched code lines are sorted in reverse character-index order (b.startIndex - a.startIndex) and updated via deleteContentRange + insertText under WriteControl.writeMode = "SUGGEST". As a result, indentation (even in whitespace-sensitive languages like Python!) and character offsets never shift, and clicking ✅ Accept All Suggestions immediately produces a 100% syntactically valid, runnable script that can be copied straight into an IDE or code editor!
  • 3. Multimodal Specification-to-Code Verification (Architecture Diagram + API Spec Table + Script): Traditional code linters and IDE extensions only see raw text files. Because DocuMentor AI is powered by the Gemini File API’s multimodal pipeline, an instructor, tech lead, or engineer can place a system architecture diagram (Figure 1), an API specification or database schema table (Table 1), and the implementation code (in Python, TypeScript, Go, GAS, etc.) inside a single Google Doc—allowing Gemini to simultaneously review the code for bugs and verify whether the implementation accurately matches the architecture diagram and specification table!

It represents a common automation task—reading rows from a Google Sheet, summarizing them with the Gemini API, and emailing the summary—written with typical beginner bugs, security risks, and API misuses:

// Sample Beginner Google Apps Script: Summarize spreadsheet tasks with Gemini and send an email
function sendDailyReport() {
  // 1. Set the Gemini API key and get the target spreadsheet tab
  var apiKey = "AIzaSyD-1234567890abcdef_HARDCODED_KEY";
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();

  // 2. Read all task rows from the sheet (Rows 2 to 50, Columns A to C)
  var data = sheet.getRange("A2:C50").getValue();

  // 3. Stop execution if the retrieved task data is empty
  if (data == "") {
    Logger.log("No task data found.");
    return;
  }

  // 4. Call the Gemini API using UrlFetchApp to summarize today's tasks
  var url =
    "https://generativelanguage.googleapis.com/v1beta/models/gemini-3.8-flash:generateContent?key=" +
    apiKey;
  var payload = {
    contents: [
      { parts: [{ text: "Summarize these tasks: " + JSON.stringify(data) }] },
    ],
  };
  var response = UrlFetchApp.fetch(url, { method: "post", payload: payload });
  var result = JSON.parse(response);

  // 5. Send the generated summary to the manager via email
  MailApp.sendEmail(
    "manager@example.com",
    "Daily Task Summary",
    result.candidates[0].content.parts[0].text,
  );
  Logger.log("Successfully sent the daily report!");
}

Look at what code_review_mode_result.jpg achieves across all three panes:

  • 1. Security Fix (PropertiesService Instead of Hardcoded API Keys): On line 4, DocuMentor AI crosses out var apiKey = "AIzaSyD-1234567890abcdef_HARDCODED_KEY"; and suggests const apiKey = PropertiesService.getScriptProperties().getProperty("GEMINI_API_KEY");—teaching the developer never to hardcode credentials in source files.
  • 2. GAS Range API Bug Fix (getValues() + Blank-Row Filtering Instead of getValue()): On line 8, beginners frequently call .getValue() (singular) on a multi-cell range like "A2:C50", which silently ignores every cell except A2. DocuMentor AI replaces var data = sheet.getRange("A2:C50").getValue(); with const data = sheet.getRange("A2:C50").getValues().filter(row => row.some(cell => cell !== "")); and updates if (data == "") on line 11 to if (data.length === 0). Look at the expanded comment reply in the center pane ([DocuMentor AI | Bug Fix (GAS API Misuse)]): it clearly explains what was wrong and why ("getValue() only returns the value of the top-left cell (A2), ignoring the rest of A2:C50. getValues() retrieves the entire 2D array of rows and columns, and filtering out completely blank rows prevents sending empty rows to the Gemini API") and states the 🎓 Learning Point (“Use getValues() instead of getValue() when reading a range that spans multiple cells, and filter out empty rows before processing”).
  • 3. UrlFetchApp.fetch & HTTPResponse Bug Fixes: On lines 19–20, calling UrlFetchApp.fetch(url, { method: "post", payload: payload }) with a raw object sends form-encoded data instead of JSON, and calling JSON.parse(response) directly on a GAS HTTPResponse object fails at runtime. DocuMentor AI suggests adding contentType: "application/json" with payload: JSON.stringify(payload) and parsing via JSON.parse(response.getContentText()).

Defensive Optional Chaining (?.) & Modern V8 Syntax (const, Template Literals, console.log): On line 23, it replaces unprotected deep property access (result.candidates[0].content.parts[0].text) with const summary = result.candidates?.[0]?.content?.parts?.[0]?.text || "No summary generated."; MailApp.sendEmail("manager@example.com", "Daily Task Summary", summary); and upgrades legacy var and Logger.log() calls to V8 const, template literals, and console.log(). 6. Quick Walkthrough of the Two Setup Workflows

Workflow A: Individual Setup (3 Minutes)

  1. Open Apps Script: Open your Google Document and click Extensions > Apps Script.
  2. Paste the Source Files: Enable appsscript.json in Project Settings (⚙️), and copy src/appsscript.json, src/code.js (into Code.gs), and src/index.html into the editor.
  3. Save Your Personal Key: Reload the Google Doc, click ✦ DocuMentor AI > Open Dashboard, paste your Gemini API key into the sidebar, and click Save. For detailed instructions, see INSTALL_INDIVIDUAL.md.

Workflow B: Zero-Code School, University & Organization Rollout (10 Minutes for IT Admins)

  1. Create a Standalone Script & Set ScriptProperties: Open script.google.com, create a new project, and paste src/appsscript.json, src/code.js, and src/index.html. Then open Project Settings (⚙️) > Script Properties, click Add script property, set Property = GEMINI_API_KEY and Value = your organization’s Gemini API key, and click Save.
  2. Publish as a Private (Internal) Marketplace Add-on: Link a standard GCP project number in Apps Script Project Settings (⚙️) and create an Add-on deployment (Deploy > New deployment). In the GCP Console, enable Google Docs API and Google Workspace Marketplace SDK, set the OAuth Consent Screen to Internal, and configure the Google Workspace Marketplace SDK with Visibility: Private (domain-only, requiring zero public review wait time).
  3. Install for Student / Researcher Organizational Units: In the Google Workspace Admin Console (admin.google.com), go to Apps > Google Workspace Marketplace apps > Apps list > Install app > Internal apps, select DocuMentor AI, and perform an Admin install for your target Organizational Units (e.g., /Students, /GraduateLab, or domain-wide). Students and researchers can immediately open any Google Doc and launch Extensions > DocuMentor AI > Open Dashboard with the organization’s API key pre-configured and locked. For the complete IT Administrator checklist and prerequisites, see INSTALL_ORGANIZATION.md.
